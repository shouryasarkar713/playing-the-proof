# Reproducing the verification

All commands run from the repository root with Node 22 and npm (`npm ci` first). Measured values are those of commit 101f955 on one machine and will vary.

| Command | What it checks | Expected result and duration |
|---|---|---|
| `npm run verify` | `tsc --noEmit` (strict), ESLint (including the import-zone rules that encode the module layering), the default Vitest project, and the production build | both pass with no reported problems; 124 test files and 1,414 tests, all passing in 157.8 s; build 134 modules transformed, a main bundle of 446.76 kB (131.89 kB gzip), a stylesheet of 42.96 kB (8.34 kB gzip) and two worker bundles of 49.18 kB and 24.01 kB, built in 0.85 s |
| `npm run test:slow` | the slow Vitest project: seeded full-game runs for k = 5, 6, 7, wider Breaker distributions, forced-region boundary stress, promotion path, larger-corpus cell checks, the cell-exhaustive k = 7 gate, the k = 8 A1 sweep over five heptagons, Overmars-29 and random 30-point sets | 13 test files and 47 tests, all passing in 2,431.9 s (about 41 minutes) |
| `npm run coverage` | default project with V8 coverage, then `scripts/check-coverage.mjs`: line gates geometry 95%, strategy / game / engine / kstrip 90% | 124 test files and 1,414 tests passing in 203.3 s; geometry 95.25% (1,043 of 1,095 lines), game 97.12% (202 of 208), strategy 91.03% (1,523 of 1,673), engine 90.51% (868 of 959), kstrip 96.07% (1,711 of 1,781) |
| `npm run audit:replays` | structural walk over `data/replays/*.replay.json`: format and version, transaction-tree linkage, `beforeHash`/`afterHash` continuity, cursor membership | 1 test file with 9 tests, all passing |
| `python -I scripts/audit/gen_fixtures.py` | regenerates `tests/audit/fixtures/*.json` from the independent exact oracle (`scripts/audit/oracle.py`, fixed seed); `tests/audit/oracle.test.ts` then compares the TypeScript kernel against it | rewrites the fixtures deterministically; the comparison test reports 23,072 comparisons over 77 check groups with no mismatch; regenerating the fixtures from the oracle script reproduced the committed files unchanged |
| `python -I scripts/audit/kstrip_oracle.py` | regenerates `tests/kstrip/fixtures/strips.json` from the literal-definition k-strip oracle; consumed by `tests/kstrip/oracle.test.ts` | seconds; the k-strip oracle test reports passing within the default tier; regenerating its fixture (1,635 strip instances over $k=1$ to $4$) reproduced the committed file unchanged |

Focused runs:

```
npx vitest run --project default tests/kstrip            # k-strip core and specification layer
npx vitest run --project default tests/kstrip/spec       # spec equivalence (57 runs), validator, predicates, replay
npx vitest run --project default tests/strategies        # k = 5, 6, 7, 8 strategies
K7_GATE_EVIDENCE=k7-evidence.jsonl npx vitest run --project slow \
    tests/slow/k7gate-cells.test.ts tests/slow/k7gate-engine.test.ts
```

Fast-tier k = 8 tests (`tests/strategies/k8*.test.ts`): 3 test files with 40 tests, all passing; k-strip specification tests: 6 test files with 165 tests, all passing. The k = 8 exhaustive gate was **not completed** (see `docs/K8_GATE.md`): the A1 step was swept over every B0 cell of five heptagons by a slow-tier test, while the deeper steps (A3, the B3 dichotomy, A4) are sampled on the preset heptagon only.

The k = 7 gate is part of the slow tier (2,431.9 s (about 41 minutes)). Its recorded evidence file for the committed results is `docs/k7-gate-evidence.jsonl` (28 hexagons / 141,466 oracle leaves; 10 hexagons / 4,255 engine leaves; 0 failures); see `docs/K7_GATE.md` for scope.

## What the results mean

- Type check, lint and the architecture test establish structure (layering, purity, single sources of truth), not mathematical correctness.
- Default-tier tests combine exact unit tests, differential tests against the Python oracles, property tests (`fast-check`) and interface tests in jsdom.
- Slow-tier games and cell checks are randomized or finite-domain evidence about the encoded strategies; they are not proofs of the published theorems.
- `scripts/audit/overmars_check.py` needs the source paper and two companion data files outside this repository and cannot run from a clean checkout; the Overmars-29 facts are asserted by `tests/slow/overmars29.test.ts` (general position; hull layers 3, 4, 7, 7, 7, 1; 5,335 convex 6-subsets; no empty hexagon; 151 empty pentagons).
- Generated output under `scripts/audit/out/` and `coverage/` is ignored by version control.

Browser evidence for the interface (Section 12.8 of the report): The production build was served locally and driven in desktop Chrome by a script that issued real clicks, typed input and key presses; the console, uncaught page errors and failed network requests were recorded throughout. No console error or warning, no page error and no failed request occurred in any run. Proof mode was started and stepped at $k=5$, $6$, $7$ and $8$, and playing a different sample after stepping back produced a sibling branch chip in each. At $k=7$ and $k=8$ the reply-class panel and the chips marked each branch as interactive, guided or not encoded before it was entered; at $k=8$ the guided `inside-pair` branch led to the escape node and, in a further run, to the verified 8-hole win card, while a placement classed as *elsewhere* (not encoded) produced the headline that the situation lies outside the encoded analysis. The *Grow to 6* and *Grow to 7* buttons on win cards started the next construction in sessions reached by sampled play. In Break the Proof at $k=5$, non-rational input and placements on an existing point or far outside the window were rejected with a message, while valid placements by click and by typed coordinates were accepted. The Sandbox accepted typed and clicked placement, undo, reset and generated point sets, switched between the monochromatic and bichromatic rules, and its bias control enforced the turn order (Maker, Breaker, Breaker, Maker at bias 1:2) and rejected invalid biases. The $k$-strip explorer ran a supported configuration with each of the three Breaker policies, showing the reason text of the first Breaker move of each, refused an over-budget configuration before running it, and classified four user-placed Breaker points in the ledger. The laboratory showed all three statuses and completed one bounded simulation, which ended by exhausting its round budget and was presented as an observation. Four shipped sample sessions loaded; the deliberately inconsistent sample and a malformed file were rejected with the entry screen preserved, and an exported session loaded again. After a reload the entry screen offered *Resume*, which restored the session at its last placement (not at a sibling branch that had been selected before the reload).

Layout was measured by comparing document and viewport widths on seven screens at each of 1280, 768 and 375 CSS pixels (21 cases): none overflowed horizontally. Proof mode and the explorer were operated with the keyboard alone, and the About and Help dialogs exposed a dialog role, a name, a focus trap and Escape handling and returned focus to their opener. A scripted audit of accessible names found no unnamed control on any audited screen.

Colour contrast was measured from computed styles on the final build, resolving each element's text colour and the composited background (with transitions disabled). An earlier measurement found light-theme text between 3.1:1 and 4.44:1 on several small tags, badges and two action buttons; after the stylesheet was adjusted, all text elements on the entry screen (56 in each theme), the $k=8$ Proof screen (44) and the laboratory (150) measured at least 4.99:1, 4.82:1 and 5.80:1 respectively in the light theme and at least 5.15:1, 5.92:1 and 5.92:1 in the dark theme. Elements drawn over gradients or images and the SVG board were not measured, and the remaining screens were not re-measured after the adjustment. Not exercised in a browser were autoplay, forking, the development overlay, Break the Proof for $k=6$ to $8$, the bichromatic and biased variants of the explorer, laboratory simulations with the greedy policy, three of the shipped sample sessions, the replay size limit, screen readers, real touch input and browsers other than Chrome. In the $k=8$ figure the win card cannot be dismissed, so the verified 8-hole is only partly visible behind it.

Provenance: the default tier, type checking, lint and the production build were last run on commit 101f955. The coverage run and the slow tier were run on the same sources apart from later changes to the stylesheet, line endings and documentation, which touch no coverage-gated directory and no test input. The Python oracle scripts regenerated their fixtures without changing any committed file.
